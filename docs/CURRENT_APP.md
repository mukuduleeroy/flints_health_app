# Flints: current app inventory

**Snapshot: 24 November 2026.** This document describes the implemented app, including unfinished behavior. It is an inventory of what exists, not a roadmap or a claim that every screen is production-ready.

## 1. Product and delivery status

Flints is an iPhone wellbeing and Christian faith companion. Its current version runs on-device, with private profiles, mood check-ins, journaling, bundled scripture, personal topic circles, a safety plan, and device management screens.

| Area | Current state |
| --- | --- |
| Product name | Flints; app text, native display name, launch wordmark and icon renamed |
| Shipping implementation | Existing React UI packaged inside a Capacitor iOS app |
| Native project | `ui/ios/App/App.xcodeproj`; scheme `App` |
| Bundle identifier | `com.flints.companion` |
| iPhone support | iOS 15+, iPhone device family, portrait and landscape |
| Visual identity | Existing sage/stone palette, Inter typography, Lucide icons and soft card layouts |
| Backend | Previous backend source, database/migrations and cloud deployment setup deleted |
| AI / LLM | Disconnected intentionally; no provider requests or scripted AI responses |
| Storage | Local device storage; no cloud account, shared database or sync |
| Simulator | Built, installed and launched on iPhone 18 Pro / iOS 27.2; welcome screen checked |
| Physical iPhone | Signed build and installation succeeded on the paired iPhone 14 Pro Max; launch was rejected by iOS security. Signature and device provisioning verified, so developer trust is the likely remaining step. Successful launch on that phone has not yet been confirmed. |
| Distribution | Development installation only; no TestFlight or App Store release completed |

The earlier Flutter implementation in `app/` remains a separate prototype. It is not the complete iPhone target described here. Its different theme and simulated behaviors should not be confused with the shipped React/Capacitor app.

## 2. Entry flow and local profiles

Three screens exist: **Welcome**, **Create Device Profile**, and **Open Device Profile**.

| Capability | Implemented behavior | Limit |
| --- | --- | --- |
| Continue anonymously | Creates a local profile with its own data and opens the app | Each use creates a new profile; after signing out, there is no UI to reopen that anonymous profile |
| Create profile | Nickname, device password, optional email, privacy acknowledgement and nickname suggestions | Creates a profile only on this device |
| Open profile | Validates a saved nickname/email and device password | Cannot authenticate an old server account or a profile from another phone |
| Password visibility | Show/hide controls on password fields | No password-reset workflow |
| Session persistence | Reopens the last active local profile after app restart | The “Remember me” checkbox does not currently change persistence behavior |
| Sign out | Clears the active session and returns to Welcome | Does not delete the stored profile or its notes |
| Privacy explanation | Explains device-only storage and the absence of backend/AI uploads | Not a full legal privacy-policy document |

Passwords are salted PBKDF2-SHA256 hashes using 210,000 iterations and a randomly generated salt. Plaintext passwords are not stored. The password checks local profile access; it does not encrypt the complete data store or add biometric authentication. The optional email is stored locally; despite an existing recovery-related placeholder, no recovery emails are sent.

Sources: [authentication screens](../ui/src/pages/auth/), [local store](../ui/src/data/local-store.ts).

## 3. Main navigation and screens

The five bottom tabs are **Home**, **Flints**, **Paths**, **Circles**, and **Profile**. Selected tabs use the existing sage indicator. Navigation remembers the selected tab and starts each destination at the top.

### Home: mood, scripture and journal

Implemented:

- Time-based greeting, with the named profile’s nickname when applicable.
- Five selectable mood values: **Rough**, **Down**, **Okay**, **Good**, **Great**.
- Mood selections saved with a timestamp on the device.
- A bundled scripture verse, reference and devotional shown after a check-in; selection uses the existing mood mapping and day-of-month rotation. It is not generated by AI or downloaded.
- Quick actions to open the companion, focus the journal, or explore paths.
- Journal writing and a Save Entry action that appears when text is entered.
- Timestamped journal history, loaded from the last 30 days of mood entries containing notes.

Important details:

- A journal entry is stored as a mood record with notes, rather than in a separate journal database. Selecting a mood and subsequently saving a journal note creates two mood records.
- New profiles start without fabricated mood or journal history.
- The 30-day display window does not mean older entries are automatically deleted.
- Journal editing, deletion, search and export are not exposed in the current UI.
- The UI inserts a new journal entry before persistence completes. A storage failure can leave it visible until reload even though it was not saved.

Sources: [HomeTab](../ui/src/pages/HomeTab.tsx), [JournalForm](../ui/src/components/JournalForm.tsx), [EntryList](../ui/src/components/EntryList.tsx), [bundled verses](../ui/src/data/verses.json).

### Flints: companion shell, currently disconnected

The companion screen retains:

- Flints branding and the original message-area layout.
- Selectable **Listen**, **Reflect**, and **Ground** modes.
- A visible **Not connected / AI disconnected** state and explanatory text.
- A disabled message field, send button and microphone button.

There is no connected model, streaming response, voice input or active conversation session. Changing modes only changes the selection. The local data layer retains conversation-related interfaces for compatibility, but the current companion screen does not create or populate conversations.

Source: [CompanionTab](../ui/src/pages/CompanionTab.tsx).

### Paths: journey catalogue and enrollment

The screen supports category filtering, journey cards, path details, local enrollment, progress presentation, and completed/current/locked step styling.

Bundled content:

| Journey | Metadata shown | Bundled steps |
| --- | --- | --- |
| Managing Anxiety | Beginner; 14-day estimate | Understanding Your Anxiety; Breathing Techniques; Grounding with 5 Senses |
| Coping with Grief | Beginner; 28-day estimate | None yet |
| Burnout Recovery | Intermediate; 21-day estimate | None yet |

The duration fields are existing metadata, not complete day-by-day programs. Filters include anxiety, grief, burnout, depression, relationships and growth; categories without content can be empty.

**Partial implementation:** the local data layer saves progress and reflections, and progress persistence is covered by tests. However, tapping a step in `PathDetailView` currently only logs the selected step. There is no working step reader, completion action or reflection form in that screen, so users cannot complete a journey end-to-end through the current UI.

Sources: [PathsTab](../ui/src/pages/PathsTab.tsx), [PathDetailView](../ui/src/components/PathDetailView.tsx), [local store](../ui/src/data/local-store.ts).

### Circles: private topic spaces

Four topic circles are bundled for each new profile:

- Anxiety Support.
- Grief & Loss.
- Daily Gratitude.
- Work Stress.

Implemented UI behavior:

- Search by circle name or topic.
- Circle details and local join/leave state.
- A member-only composer with a 500-character post limit.
- Local posts, optional anonymous posting, replies and anonymous replies in the circle detail view.
- “Relate” reaction toggling.
- A combined feed from joined circles and nested reply rendering.

These are personal topic spaces, not a live community. Data is separate for each local profile. A circle’s membership indicator represents that profile joining locally; there are no remote participants or cross-device posts.

The storage layer also supports flags, hiding and deletion, but the post card’s overflow button has no handler. A normal user cannot currently flag a post from that menu. Creation is available through Device Tools; full editing/archiving is not wired into the circle management screen.

Sources: [CirclesTab](../ui/src/pages/CirclesTab.tsx), [CircleDetailView](../ui/src/components/CircleDetailView.tsx), [PostCard](../ui/src/components/PostCard.tsx).

### Profile and safety plan

The profile screen includes:

- Nickname, initial avatar and local profile creation date.
- A streak derived from days containing mood records.
- Mood-log and conversation counts from local data.
- A milestone card; automatic milestone awards are not implemented, so new profiles show zero.
- A last-seven-days mood-history chart.
- Sign out and access to **Device Tools**.
- A settings icon with no settings workflow attached yet.

The safety-plan modal stores eight sections:

1. Warning signs.
2. Things I can do on my own.
3. People who can distract me.
4. People I can ask for help.
5. Professional contacts.
6. Emergency contacts.
7. Making my environment safe.
8. Reasons for living.

List items can be added through the current native/browser prompt and removed; the environment section is free text. **Save Safety Plan** persists the changes locally. The plan is not automatically shared, monitored, or sent to contacts. There is no emergency-call or automatic escalation integration.

Sources: [ProfileTab](../ui/src/pages/ProfileTab.tsx), [SafetyPlanModal](../ui/src/components/SafetyPlanModal.tsx).

## 4. Device Tools

Access is through the Profile tab. The retained administrative layout is labeled **Flints Device Tools**, with explicit on-device scope. Local profiles receive device-owner access; this is not a remote organization’s authorization system.

| Destination | What exists | Current boundary |
| --- | --- | --- |
| Dashboard | Summary cards and shortcuts to management screens | Local data only; no live platform operations or automated risk assessment |
| User Management | Lists/searches saved local profiles and shows details | Cloud role changes and suspension are disconnected; some inherited wording mentions UUID search, but the current search implementation filters nicknames |
| Content Moderation | Displays locally flagged posts and hide/unhide review actions | Normal post-menu flagging is not wired up; remote escalation reports that it is disconnected |
| System Monitoring | Local moderation counters and explicit disconnected AI/safety-filter status | No model uptime, health service or operational AI filter |
| Circle Management | Lists circles; creation form for name, topic, description and icon | Edit/archive controls are not wired up |
| Path Management | Lists journeys; creates metadata; local publish/unpublish and delete | Creating a path does not author its steps; no step editor exists |
| Safety & Crisis | Retained screen structure and a disconnected-monitoring message | No remote risk assessments, assessed users or escalation service |
| Analytics | Counts local profiles, circles, posts, enrollments, moods and conversation records | Export Report has no handler; some inherited trend/percentage labels are not backed by a complete time-series analysis |

Metrics require care: some summaries combine total profile counts on this device with content counts for the active profile. The mood average labeled “this week” currently uses all stored moods for that active profile. Zero risk counters do not establish that the person has been assessed or is safe. Static resource text on the retained safety screen is not a connected, location-aware support service.

Sources: [device-tool screens](../ui/src/pages/admin/), [AdminLayout](../ui/src/components/admin/AdminLayout.tsx), [local store](../ui/src/data/local-store.ts).

## 5. Storage, privacy and removed services

| Data | Storage / behavior |
| --- | --- |
| Profiles and per-profile content | Versioned JSON in WebView/browser `localStorage`, key `flints.device.v1` |
| Active profile | Local session key `flints_session`; identifies the selected profile, not a server-issued bearer token |
| Navigation | Selected member tab, tool destination and tool mode persisted locally |
| Password material | Random salt and PBKDF2 hash; no stored plaintext password |
| Journal/moods | Timestamped records; journal text is the mood record’s `notes` |
| Circles and posts | Active profile’s private local content, including reply relationships and reactions |
| Safety plan | Active profile’s local eight-section object |
| Paths | Bundled catalogue plus local changes and enrollment/progress data |

Current boundaries:

- No backend process, database server, Redis, WebSocket chat service, model client or provider key is required by the iPhone app.
- No cloud account, synchronization, remote community, automated safety assessment or remote moderation is connected.
- Old server accounts and data have not been migrated.
- There is no in-app backup, export/import, profile deletion or restore workflow.
- Uninstalling the app or clearing its data can remove local profiles and notes. Data is not guaranteed to transfer to another device.
- Profile separation is application behavior within one local store, not per-profile database encryption.
- A damaged or unsupported stored-data format produces a read error rather than being silently replaced. Storage-write failures also produce an error in the data layer; individual screens may not surface these errors equally well.

The old root `.env.production` remains unused. It was preserved after deletion was rejected by automatic approval review because it could contain deployment secrets. The application has no code path that reads it.

## 6. iPhone adaptation and UI reference

Implemented platform adaptations include:

- Safe-area spacing for the notch/Dynamic Island, home indicator and landscape edges.
- Shared viewport-height handling for Safari and the native keyboard-resized WebView.
- A contained scrolling chat area and composer layout, although chat input is currently disabled.
- Mobile inputs sized to avoid unwanted focus zoom, and enlarged touch targets in key controls.
- Responsive member navigation, narrow-screen headings, admin menus and horizontally scrolling tables.
- Safety and management dialogs constrained to the available viewport, with internal scrolling.
- Locally bundled Inter weights 300–700, reducing dependence on external font loading.
- Light appearance, Flints launch wordmark and a generated Flints app icon.

The `/design-system` route provides a browsable source-based UI reference: foundations, tokens, 15 reusable React components, 16 screen references, live specimens and clearly labeled pattern demonstrations. Demo submissions in that library are separate from actual profile data. The reference also shows the separate Flutter theme; switching its palette is not an app theme switch.

There is no completed dark mode, full accessibility certification, finished settings system or claim of complete iPhone behavioral QA. Some original low-contrast text, focus/dialog behavior and utility controls still warrant follow-up.

Sources: [iPhone CSS](../ui/src/iphone.css), [platform setup](../ui/src/platform/iphone.ts), [design system](../ui/src/design-system/).

Run from `ui/`:

```sh
npm ci
npm run dev          # App at /; UI reference at /design-system
npm run build        # Production web bundle
npm run test:offline # Local persistence and disconnected-AI checks
npm run test:iphone  # Build and responsive browser checks
npm run ios:sync     # Build/copy current UI into native project
npm run ios:open     # Open Xcode for signing and device deployment
npm run ios:build    # Unsigned iOS compilation check
```

`ios:release` currently only builds and syncs assets; despite its name, it does not sign, archive, submit or publish an app. See [iPhone setup](../ui/IPHONE.md) and [testing guide](../TESTING_GUIDE.md) for the related workflow.
